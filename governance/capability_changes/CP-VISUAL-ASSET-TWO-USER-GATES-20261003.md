# 视觉资源的两次用户审批与切图协作

- 类型：`CROSS_AGENT_CONTRACT`
- 授权：2026-10-03，用户明确要求先拆开单元示例、先做空场景，并将协作顺序改为“出资源前用户审批 → 美术与程序沟通切图 → 切后效果再由用户审批 → 程序正式使用”。
- 范围：所有后续正式视觉资源任务的组织级流程；当前游戏立即在空场景下一安全交接点采用。其他既有游戏仍保持各自 pinned 版本，不自动升级。

## 决定

`rules/visual_production_contract.md` 规定两个独立 Artifact Gate：美术制作方案获用户批准前不得输出拟进入正式资源的图片、母版或切片；获批后 Art/Tech 首图前预签和样张评审仍执行。Art 完成原创源时与 Tech Lead、Client 协商切图，提交切片清单、同尺度重组和视窗效果，经 Art/Tech 分别评审后再由用户批准具体版本。第二门禁通过前 Client 不得正式接入，批准后仍须 Client 运行验证与 QA。

制作方案的批准只授权制作，切图效果的批准只授权交程序正式使用；两者不能替代，也不等于整个功能已完成。既有概念/探索稿留历史，不凭旧预签或旧审批继续生产。用户本轮附件是空场景方案的视觉参考，不自动成为可裁切的资源；实际来源/许可与相似风险仍需核验。

## 双同步与验证

本轮同步当前游戏的 `AGENTS.md`、工作流/审批/资源契约和受影响角色配置，同时同步主 `YuanQuan/ai-studio-template` Studio Layer 与 `templates/game/` 的空白美术/资产默认项。核 Schema、文件一致性和两仓库提交范围；不把百鬼夜市的玩法、美术图或项目任务写入主模板。当前项目的第一次具体审批对象是空场景出资源前方案，**该方案尚待用户单独批准**；用户对本流程变更的授权不得冒充对方案的批准。
