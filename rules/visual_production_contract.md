# 视觉设计到正式资源的交接契约

本规则适用于场景、角色、建筑、道具、UI 和 VFX 中需要制作图片或运行画面的任务。它规定各角色如何继承已确认的视觉设计，并与 `rules/artifact_contract.md`、`rules/approval_protocol.md` 共同使用。具体游戏的画风、配色、角色形象和资产数值仍由该游戏已批准的 Art Artifact 与 `project/ART_GUIDE.md` 决定。

## 1. 设计基线与原创重绘

- Art Director 将用户批准或明确采纳的效果、概念和设计意图转成有版本号的视觉基线。正式生产前，`VISUAL_ANCHORS.md` 或等价 Art 文档逐项写明：轮廓/比例、视角/构图、材质/明暗/光感、色彩关系、身份元素、动作/状态、空间/遮挡、实际显示尺度，以及每项必须保持、可调整和需重新审批的范围。
- 效果图与概念图是设计依据，不自动成为可裁切、可描摹、可直接导入的生产图片。首次正式制作须在来源和权利允许的前提下形成完整的多图层 PSD 可编辑母版，并登记参考来源、许可、工具/字体权利和可识别相似风险。已有资源先评估在当前 PSD 上定向修改能否达到已确认效果；若局部修图在同背景、同视窗和实际显示尺度下仍有明确视觉差距，Art 可选择重绘并记录差距、原因、范围、来源及旧版保留方式。重绘应延续已确认的视觉目标和产品语义，不能机械复制受保护表达，也不能借技术适配自行更换造型、材质或视觉主次；制作方案及受影响锚点按现行用户审批和 Art/Tech 预签办理。
- 产品、镜头、动画方式或技术约束变化时，先列出原锚点中仍有效、失效和待决定的部分。只有实际受影响的锚点重新评审；不得把技术方案退回误当作所有视觉设计一并作废。
- 若制作工具无法直接生成 PSD，Art 使用 `bggg-creator-image2psd` skill 将当前已确认图片或现有分层资源转换为 PSD。转换保留原图尺寸、位置与可见效果，保存源图、转换预览、图层来源及验证记录；平面图拆层的可编辑程度和补洞/重建部分须如实标明。转换本身不授权重新绘制或改变已批准效果，视觉差异仍须进入 Art Review 与相应审批。

## 2. 出图与审查顺序

1. Master 的 Task Packet 引用已批准视觉基线，列出可检查的视觉验收和必需证据；Product 负责玩法/内容语义，Art 负责视觉解释。
2. **资源制作前用户审批**：Art 先提交有版本的制作方案，说明实际参考及权利状态、视觉锚点、对象边界、画幅/显示尺度、拟制作源与切图思路，以及不确定项。Master 向用户呈现可审阅的方案，Producer 记录该方案的 `USER_APPROVED`。用户未批准前，不得绘制、生成或导出拟进入正式资源的母版、样张、切片；既有探索图只能标为历史候选，不能据旧预签继续出图。方案获批仅授权进入资源制作，不代表最终图片或切图效果获批。
3. 获得上述批准后，代表样张首次出图前 Art 与 Tech Lead 对同一版本的来源/版权、母版格式、尺寸/画布、层/支点、帧/骨骼、图集/合批、目标设备预算与输出范围分别签认文字预案。签认只覆盖所列批次和工具；全量资源开工前以及换源格式、工具、尺寸、动画或资源范围时，在下一张图生成或导出前复签。尚无实图的预签只能写估算，不能伪称实测。
4. 高影响或将批量扩展的资源先做可编辑代表样张。Art 将已确认效果、被退回版本（如有）与本轮 PSD 修订或重绘稿放在同背景、同画幅、同游戏视窗和实际显示尺度下并排，对每个视觉锚点记录 `PASS`、`REVISE` 或 `NOT_TESTED`、证据路径与原因；局部修订若仍未达目标，可在已获批准的制作范围内改用重绘并记录方法变化，必要时按第 3 条复签，视觉目标或范围变化则修订方案并按原有 Gate1 审批。未通过的样张不得扩成整批。低影响单件可在成品评审中直接完成同样对照。
5. 代表样张先由 Art 对实图给出视觉结论，再由 Tech Lead 按实际 alpha 范围、页数、贴图面积和投影像素复核生产方案；两者均通过且全量预案复签后才扩为整批。通常成品分别取得 Art 视觉结论与 Tech 对实际贴图、内存、打包、合批和兼容性的结论。第 6 条的自行切图／用户提供 PSD 与导出 PNG 例外不以这两项成品 Review 作为切图效果用户审核的前置条件；接入后仍核真实运行指标。哈希、alpha、帧数、脚点、构建或性能 `PASS` 均不替代用户对具体效果的审核。
6. **切图协作与再次用户审批**：Art 完成或修订 PSD 整体母版后，与 Tech Lead、Client 讨论切片边界、前后遮挡、复用、纹理/图集、接缝、缩放与性能；切图方案和变更留档。Art 负责从当前 PSD 拆分图层，或按确认方案合并图层后输出图片，提供 PSD 版本、图层到导出图的映射、输出清单、同一画面重组及目标视窗效果。拆分、合并和导出以保持母版效果为准；不影响效果时不得额外修改图片，必要技术处理只作最小调整并记录。通常由 Art 和 Tech Lead 分别复审切图效果后，Master 呈用户审批。**若由本组织 Agent 自行切图，或直接采用用户提供的 PSD 与其导出 PNG，则不设置切图效果的 Art/Tech/Master 复审或额外预览环境门禁**；执行 Agent 核对文件、版本、图层映射与同尺度重组，向用户直接展示实际切片、重组效果、资源清单及已知技术限制，由用户审核具体版本和效果。用户明确批准前，Client 不得将切片作为正式工程资源接入。切图改变已批准外观时先修订视觉方案并重新审批受影响项。
7. 自行切图路径的文件与重组核对是交付说明，不是替代用户判断的专业视觉批准；用户退回后以新版本重新提交。其他生产路径沿用逐锚点 Art 自审、Tech 生产 Review 和 Master 复核。两次用户审批分别对应制作方案和切图效果，不能相互代替。
8. 切图效果获用户批准后，Client 才在同源版本的独立/组合/主体入口正式接入，并核实际视窗、状态、翻转、光影、遮挡和资源 ID，记录源/导出/Prefab 的版本、UUID 或 hash，保留截图/录屏与性能记录。实际运行画面须与已确认效果在同背景、同视窗和实际显示尺度下对照，发现视觉落差据实进入现有修订流程；静态切图或同尺度重组通过不等于运行效果符合。正式功能由 QA 以已批准视觉基线做固定环境的视觉验证，按功能、视觉和性能分别报告；单元示例不安排 QA，示例 Owner 记录相应检查证据，升级为正式功能或正式资源接入后重新办理 QA。依 `rules/qa_protocol.md`，`FUNCTIONAL` 默认固定 Web/测试环境，`RELEASE` 才要求声明平台真机；示例若另有目标机要求，须在获批任务规格写明设备、环境和阈值。未导入、未运行或无相应设备证据时明确 `NOT_TESTED`，静态预览不充当运行证明。

## 3. 技术与视觉冲突

画布、贴图页数、压缩、复用、帧数、骨骼、合批或设备预算均不自动授权改变已确认的视觉设计。若目标无法同时满足，Art 说明具体视觉损失，Tech Lead 给出测量或可复验估算、备选尺寸/分页/实现方式和成本；Master 组织受影响角色评审并把需要用户取舍的变化提交用户。未经决定不得把画面静默简化成示意图，也不得隐瞒实际性能超限。

## 4. 各角色交接

| 角色 | 必须负责的界面 |
|---|---|
| Product | 标明视觉元素承载的产品身份和不可改变的语义；不自行指定艺术画法。 |
| Art / Art Director | 提交资源制作前的用户审批方案；获批后锁定视觉锚点，负责多图层 PSD 整体母版、对已有资源局部修订或在局部方法不足时有据重绘、图层拆分/合并后的图片输出，和 Tech Lead/Client 讨论切图；自行切图时直接提交实际结果和核对记录给用户。 |
| UI / VFX | 在 Art 基线内完成各自结构、交互或触发/时序/性能规格；视觉偏离先提方案交 Art 评审，不以复用或降级自行换风格。 |
| Tech Lead | 资源制作前参与预算预签，切图时与 Art/Client 核层、图集和性能；自行切图路径不设置其切图效果前置复审，正式接入时核真实资源与运行指标；预算冲突上报取舍。 |
| Client | 可在正式接入前提供切图与视窗技术意见；只在切图效果获用户批准后正式接入该资产版本与源 ID，程序适配改变锚点时回 Art 评审，留下运行证据。 |
| Server | 若服务端配置引用视觉资产，仅维护获批稳定 ID/版本和数据语义；不以服务端字段/占位资源决定美术外观。 |
| QA | 分别核功能、运行性能和视觉锚点；缺少基线、画面或设备证据时记 `NOT_TESTED/BLOCKED`，视觉偏差按现行缺陷等级与审批门禁处理。 |
| Producer | 分别追踪制作前方案和切图后效果的用户审批及各自版本、执行源；通常追踪视觉/技术 Review，自行切图路径核用户直接审核记录；任一用户门禁未过或版本错用时锁下游。 |
| Master | 组织跨角色取舍，先呈制作方案供用户审批；自行切图路径直接呈切片与重组效果供用户审核，其他路径按专业 Review 呈报；不代替用户判断。 |

## 5. 最小证据与版本

需视觉基线的 Task 至少引用：制作前用户已批准方案、批准的 Art Direction/概念版本、`VISUAL_ANCHORS.md` 或等价锚点文档、版本化多图层 PSD 整体母版、旧版修订或有据重绘的来源与差距记录、图层拆分/合并与导出映射、输出图片清单、切图协作记录、同背景同尺度重组/视窗效果、**切图效果的单独用户批准记录**。通常还需 Art 视觉 Review 与 Tech 资源 Review；自行切图或采用用户提供的 PSD/导出 PNG 时，切图效果环节以执行 Agent 的文件核对和直接提交用户审核替代这两项前置 Review。适用时还需动画/状态视频与运行证据。每项结论须对应真实文件路径和版本；失败样张、用户退回稿保留历史，修订版不得覆盖旧审批。新规则只约束新任务和当前任务在安全交接点之后的新版本，不追溯伪造旧版 `PASS`。
