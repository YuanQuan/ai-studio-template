# 已批准效果的还原与算力控制契约

版本：v0.1。状态：`USER_APPROVED / ACTIVE`；用户于 2026-10-12 明确批准本版本。与 `rules/visual_production_contract.md`、`rules/artifact_contract.md` 共同使用；不替代既有制作方案 Gate1、具体资源效果 Gate2、自产切图直送用户和适用 QA。

## 1. 验收目标与边界

通过的效果是后续制作的基准。分层、修改、动画和技术优化都须证明对已批准效果的继承，不能仅以“风格相近”“文件有多层”或技术检查通过结案。将“完美还原”落实为以下三类可检查目标：

| 情况 | 验收目标 | 无法直接保证的部分 |
|---|---|---|
| 同尺寸、同姿态、同显示管线的无损拆层与重组 | 重组可见像素与冻结图一致；未获准变化区域差异为零 | 原图没有的独立物体信息、被遮挡内容、复杂混合层的原生编辑能力 |
| 局部细节修改 | 未改区域保持原样；批准的修改区按新目标验收 | 修改区不能同时与旧像素完全一致；其成为新的批准版本 |
| 序列帧或骨骼动画及实际游戏画面 | 基准姿态复现已批准效果，运动中保持身份、材质、配色、光感与批准的动作范围 | 新角度、形变和露出的隐藏内容须补充设计；静止图片不能证明所有动态效果 |

无损目标失败时提交差异和原因，不静默改成“差不多”。运行缩放、压缩、采样、混合与色彩转换可能引入差异；在制作方案中固定具体环境、允许误差及不可妥协锚点，再由用户批准。不设置可掩盖小面积关键细节的通用百分比，也不事后放宽阈值。无允许误差定义时，源图静态重组采用零差异目标；运行或动态结论保持 `NOT_TESTED`，直到补齐对应依据与证据。

## 2. 冻结基准与单一母版

Art 在现有制作方案内使用 `agents/art/VISUAL_FIDELITY_PACKET_TEMPLATE.md` 或等价小节记录，不另造重复事实源：

- 已批准效果的实际文件、版本、SHA-256、批准记录、尺寸、透明度、色彩解释、背景、视窗、缩放与基准姿态。效果原件只读保留，不被转换稿、重绘稿或技术预览覆盖。
- 当前唯一工作母版 PSD 的版本和路径、图层稳定 ID、层级/混合/遮罩/位置/支点、图层到导出及动画附件的映射；源版本 → 导出版本 → 运行资源身份链引用现有资源登记。
- 必须锁定的轮廓/比例、视角/构图、脸与字形、识别装饰、材质与纹理、明暗与色彩关系、遮挡与实际显示尺度；列明允许变化区域和动作范围。
- 图层类别：原始可编辑层、保留原像素的拆分层、补洞/重建层、整体参考层。平面图转换出的层如实标可编辑范围，不能声明恢复了原来不存在的隐藏信息或原生笔触。

尚无 PSD 时先检查已批准图及现有资源的实际可编辑性，确定最小必要的语义层。需要独立修改或动画的部件才独立成层，静态不动区域允许作为完整栅格层保留。使用 `bggg-creator-image2psd` 时沿用已确认图片并遵守该 skill；不得为增加图层数量重新生成整张图。

参考原图层可以保留，但校验重组时必须关闭参考层或旁路覆盖层，独立导出实际交付层再重组。只有顶层整图盖住底层碎片的 PSD 不能证明语义分层、编辑能力或可动画性。需独立运动的层必须检查单层可见范围、边缘、与其他层的关系及实际运动暴露区域。

## 3. 多层输出

1. 优先直接导出现有层，或从当前母版进行确定性的拆分/遮罩/合并；保留尺寸、色彩、位置、边缘和混合语义。复杂遮罩、半透明叠加或不可移植混合效果先做代表层验证，必要时将效果烘焙进适合的层，不静默丢失光影。
2. 固定统一画布/坐标、裁切偏移、支点、顺序、混合方式与导出设置。母版含视窗外区域时既核整体，也核批准的视窗。
3. 分别核 PSD 导出的整体、实际交付切片重组与冻结图；输出并排、叠加或闪烁对照和差异图。比较配置固定并保留版本：解码工具/版本、位深、ICC/工作色彩空间及转换方式、直通或预乘 alpha 的归一处理、合成背景、混合/采样与区域遮罩；归一后的两对象在同配置下比较，零差异不能跨未统一的管线断言。差异记录包含比较对象 hash、配置版本、环境、区域、最大差异和变化像素数；完全透明像素中不可见 RGB 不能冒充视觉漂移，alpha 和可见区域须单独核。文件 hash 用于身份，解码后的像素比较用于还原判断。
4. 只要不发生获准变化，保真区域不许补画、锐化、放大重绘或重新生图。剪切后出现缺口、边缘污染或光影不匹配时，先定位遮罩/混合/坐标，确认存在原图缺失信息后才在获批范围内补洞。
5. 交付真实切片、映射、重组证据与限制；自产切图和用户 PSD/PNG 路径仍直接交用户 Gate2 审核，不增加专业效果复审或额外预览环境门禁。

## 4. 细节修改与版本失效范围

- 修改前登记目标部件、区域/遮罩、理由、保留锚点及可能连带影响（投影、遮挡、透光、边缘）；关联现行方案批准范围。改变原批准视觉语义须按原流程修订方案。
- 在当前 PSD 局部改层；优先已有笔画、遮罩、参数和部件复用。确需生成式修补时只提供所需区域与必要上下文，保护其他区域；不得靠反复整图生成匹配旧稿。
- 修改后核未改区域零差异，以及修改区和所有受影响光影/遮挡区域的视觉结果。扩大区域必须先说明并检查既有授权，不能扩大遮罩以隐藏差异。
- 只重导受影响层、帧、图集页或依赖组合；未受影响资源保留 hash/版本映射。旧母版与批准图留档，新版批准不倒写旧审批。
- 局部方法失败需重绘时，按现行契约记录同环境差距、最小重绘范围、来源与旧版保留；更改方案/批次/工具时重新办理受影响审批和预签。重绘不授权降低还原目标。

## 5. 序列帧输出

- Art 负责角色/部件视觉源和图片输出；VFX 负责其职责内的特效时序/动作规格；Client 实现，Tech 核实现与预算。角色动作不因选择序列帧而自动改变角色职责。
- 制作方案固定动作/状态、方向、时长、帧率、是否循环、基准帧、起止/循环接缝、支点、画布、挂件/遮挡关系与关键姿态。没有确认动作时不得批量猜测帧或角度。
- 优先从同一套获批图层/部件通过确定性变换、已确认关键帧和合适插值导出；只为无法表达的局部动作补绘关键图。不得逐帧独立整图生成为默认路线。
- 先做一个代表动作或最短可检验片段，涵盖基准姿态、最大位移/变形、遮挡变化及循环接缝；验证画面继承和技术可行性后再批量导出。插值导致的扭曲、穿帮、身份漂移不能仅凭流畅性接受。
- 自动结构检查可遍历全部帧：帧数、顺序、尺寸、支点、透明边和文件身份；人工视觉先核代表片段、关键帧和异常帧，再看完整动作回放，必要时针对异常段逐帧核，不反复无差别检视全部帧。
- Gate2 提供帧清单/序列源、播放参数、代表关键帧和完整循环/动作预览；正式接入后记录同环境实际回放，不能用静态接触表代替动态还原。

## 6. 骨骼动画输出

- 只在所需动作适合现有分层且目标运行时可支持时选骨骼；由 Art/Tech 比较视觉损失、准备/返工成本与运行预算。不得为了“骨骼省算力”强行变形有立体材质、复杂透视或高识别细节的对象；必要时使用局部序列帧与骨骼的混合方案，不预先指定新工具或购买许可。
- 复用获批部件贴图。固定骨骼/槽位 ID、坐标/支点、参考姿态、网格/权重、约束、附件、绘制顺序、混合、导出工具与运行时兼容版本。原生骨骼源文件与导出骨骼数据/贴图保留实际可编辑路径，PSD 不能替代可编辑绑定与时间线。
- 绑定后的基准姿态按冻结图核对；绑定姿态可以与图稿姿态不同，但验收须能复现图稿姿态，不能只展示无关的 T/A 姿态。
- 最小样片检查最大弯曲/拉伸、转向、附件连接、面部细节、光影随动、前后遮挡、缝隙与循环接缝；需动画但被遮挡的部位仅补到已批准动作实际会暴露的范围。
- Gate2 包含可编辑源、数据/贴图版本、基准姿态对照、代表极值帧、完整动作预览与已知限制；Client 接入后用实际运行时再核，明确导出预览与真实运行的差异。

## 7. 算力与返工预算

预算属于同一制作方案与 Art/Tech 预签，不新增独立用户门禁，也不授权额外费用或工具。把制作投入与运行负载分别记录，不能用图片制作成本推断 GPU/内存已通过。

| 环节 | 默认处理 | 记录与停止条件 |
|---|---|---|
| 诊断 | 先核源文件、差异和编辑能力，选择最小处理路线 | 证据不足先补检查，不把问题直接交给整图生成 |
| 无损拆层/导出 | 确定性本地处理优先，预计生成调用为 0 | 若需补洞/生成，先核方案是否包含该范围与预算 |
| 局部修改/新关键姿态 | 一个代表区域/片段先行，按当前编辑粒度制作 | 未通过代表样片不得扩全量；不为同一缺陷盲目换提示重试 |
| 扩批 | 复用已确认部件/绑定/关键帧，批量导出与缓存 | 仅重算失效项；输入/设置/工具变化才重建相关缓存 |
| 失败处理 | 每轮先解释差异和可检验的修正假设 | 同一问题默认最多两轮自动修正，累计计数不因换任务、换工具或换提示清零；仍失败停止该支线并提交诊断 |
| 预算超限 | 对照获准批次上限，提交已有成果与最小下一步 | 达到调用、候选数、耗时或费用中任一上限停止，走现有变更/预算决定；不能先超额制作 |

预案记录各阶段计划候选数、生成调用上限、修正轮次、制作时间上限及已知费用上限。没有费用/算力遥测时写“未知”，使用可核调用数、候选数和墙钟作代理，不能虚构 GPU 小时或节省比例。0 调用路线无需购买或调用生成工具；需要生成的批次应在开工前填入可核数字，不能用“尽量少”代替上限。

执行账本最少记录：输入/设置/工具版本、输出实际路径/hash、确定性处理或生成调用、调用成功/失败/未知状态、候选数、返工原因、起止时间、已知成本与剩余额度。记录工具返回的请求 ID 与可用幂等键，不虚构工具未提供的能力；结果未知的调用先按 ID 查询原结果，不盲目再发起同一高成本请求，工具无法查询时明确未知并停止重复提交；无法确认消耗时保守计入潜在预算。提示/输入/工具版本共同决定生成缓存身份；确定性导出还要包含源层、遮罩、尺寸、色彩、混合与动画参数，不能只凭文件名复用。

代表样片成功后，后续验证按变化与风险聚焦；已核的相同文件和条件不重复生图、不重复整批渲染。项目调用账本可引用既有日志，不强制开发新平台。自动预算拦截器、像素比较器或骨骼工具未实装时如实注明“人工执行约束”，文档不冒充可用软件。

## 8. 证据、批准与迁移

同一制作方案可容纳全部记录，最小提交为：冻结基准/锚点、母版/语义层及导出映射、变更范围、预算与执行账本、静态重组/差异、适用动画源与回放、实际运行证据及 `PASS / REVISE / NOT_TESTED` 范围。通过哈希、数量或平均相似分不能单独证明视觉通过。

Art 负责源及视觉继承；Tech 负责可执行方法、预算和兼容性；Client 负责同版接入与运行；正式功能 QA 按适用范围独立判断，示例由 Owner 记录证据。Producer 在现有任务/版本/审批记录中追踪预算消耗、源版本和失败停止；Master 呈交具体成果及真实取舍。

本规则 v0.1 已获用户批准，状态与角色方法索引随本次启用同步，新制作方案引用它；执行中的任务在安全交接点列出差异并迁移。只重核受影响锚点与资源，不追溯改写旧批准或要求全库重做。当前游戏和 Studio 主层及标准项目模板同步，其他游戏保持 pinned。规则批准不等于任何新图、动画、资源接入或 QA 获批。
