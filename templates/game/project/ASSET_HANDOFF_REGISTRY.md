# 美术交付与客户端正式资源登记

本文件是美术交付文件到客户端工程正式资源的唯一目录映射。新项目初始为空；只登记实际获准交付的资源或明确标为“计划”的接入项，不把概念图、母版、审阅合成图写成运行纹理。本表与 `project/ASSET_MANIFEST.md` 互相引用，后者负责美术资产清单和视觉状态，本表负责交接路径与工程身份。

## 记录与维护

- Art 核对资产 ID、描述/用途、美术交付目录与文件、格式尺寸、版本/哈希及资源审批依据。
- Tech Lead 与 Client 在首次正式入库前确定本项目的 Cocos 目录和命名方案；Client 导入后填写真实工程目录/文件、`.meta`、图片主 UUID、Texture2D/SpriteFrame 子资源 UUID、Prefab UUID 与 Scene 引用、导入设置和提交版本。
- 目录与文件须分别记录。未导入时工程目录和文件可写候选，但状态必须是 `PLANNED`，UUID 写“待生成”；只有真实导入并核对后改成 `IMPORTED`。替换或废弃保留历史版本和映射，不静默改名、复用旧 UUID 或覆盖用户批准的美术源。
- 文档更新依附对应 Art/Client/Tech 的正式 Artifact 与 Review，不单独产生新的用户审批门禁。

## Cocos 新正式资源命名默认规则

- 工程内新正式资源路径使用 ASCII 小写 `snake_case`，不用空格、中文、临时序号和含义不明的 `final2`；按模块和资源类别分目录，例如 `assets/game/<module>/<category>/`。实际目录由项目技术规格锁定。
- 文件名表达类型、模块/对象和语义，避免同名：纹理 `tex_<module>_<object>_<part>.png`，Prefab `pf_<module>_<object>.prefab`，Scene `scn_<module>_<name>.scene`；其他类型按实际需要制定前缀，避免凭文件名推断纹理配置或运行状态。
- 版本、批准状态与哈希记录在本表和正式 Artifact，不依赖频繁改名；Creator 自动生成的 `.meta`/UUID 视为工程身份，正式导入后不得随意删除重建。已有工程资源不因本默认规则批量重命名。
