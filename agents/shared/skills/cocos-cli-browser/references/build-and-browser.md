# Creator CLI、HTTP 与浏览器验证

## CLI

读取项目锁定版本和已有构建配置，使用实际安装的Creator命令行。Creator 3.8示例：

```text
CocosCreator.exe --project <项目绝对路径> --build "platform=web-mobile;debug=true;configPath=<已核配置路径>"
```

参数和路径使用运行shell正确引用；不要直接拼接不可信文本。Windows后台启动使用隐藏窗口，避免额外可见编辑器；记录自己启动的进程。执行环境确需沙箱升级时使用正式审批机制；沙箱升级不等于系统管理员，不修改系统ACL/安全设置来“修复”构建。不要把某台机器需要升级执行环境写成所有项目必须UAC提权。

Creator 3.8官方CLI退出码32=参数错误、34=构建失败、36=成功；其他版本从其文档/实际完成日志判定。退出码只是证据之一：等到实际构建任务结束，核当前日志、目标输出时间/内容及入口依赖。父进程/启动器先退出时继续观察已启动的构建进程和日志，不能立刻宣布成功。缺少当前产物、失败依赖或残留missing UUID时不把旧build目录作为新产物。

不与同项目的Editor/另一CLI任务争用资产数据库；必要时等待任务结束，或用明确的隔离工作副本执行探测，记录副本与正式代码身份。不要复制其他游戏状态或把探测输出提交正式源码。

独立[官方cocos-cli](https://github.com/cocos/cocos-cli)与Creator内置CLI是两套工具；未验证当前项目序列化/引擎兼容前不安装替换或升级引擎。Creator内置构建CLI通常不会提供任意Scene编辑命令，也不能保证所有平台完全无GUI环境。

官方参考：[3.8命令行构建](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-in-command-line.html)。构建不代表设备或平台验收通过。

## HTTP实际产物

将当前构建的输出目录用项目已有静态服务提供，默认绑定127.0.0.1/localhost。用未占用端口，不终止未知服务。核入口HTTP状态及服务根目录，记录构建配置、源码/输出hash、进程、URL、验证时间。开发阶段可用Creator预览，但须标明，不冒充刚构建版本。没有现成服务时可用环境可用的标准库HTTP服务；长期复用工具应跟踪进程和退出方式。

## Codex内置浏览器

使用当前可用浏览器工具的正式入口，选 `iab` / Codex In-app Browser。第一次只执行规定的创建/选择入口，先读取返回文档再行动。`cua_repl`可用时示例：

```javascript
var gameTab = await cua.createBrowserTab("iab", "http://localhost:<端口>/", { visible: false });
```

复用绑定；后续以当前返回文档决定截图、DOM、坐标、拖动、滚轮、控制台和viewport支持，不能假设所有后端都可执行所有API。需要用户观看或交付时显示/保留标签；否则验证在后台进行。不要直接用终端Playwright/CDP代替内置浏览器而称其为已验证。

- DOM控件：以当前DOM定位。Cocos Canvas内部按钮通常没有语义DOM，依据最新截图定位并用该工具已公开的坐标点击/拖动；每次动作后获取对应证据。viewport变化后重新截图和定位。
- 如果后端只支持DOM且没有Canvas坐标输入，截图可用于视觉检查，但交互项记NOT_TESTED/BLOCKED；只能使用已有、明确获批且测同一业务路径的测试入口，不能注入状态冒充真实手势。
- 可用控制台/网络错误接口用于检查missing资源、脚本异常、入口加载失败。只读DOM evaluate不能做引擎对象探查、调用游戏方法、dispatchEvent或修改状态。
- 按Task批准范围验证进入/返回/重入、拖动/缩放/重置、UI隔离、必要视口与视觉；不自行扩展设备矩阵或降低性能/视觉门槛。
- 浏览器权限/安全拒绝是阻塞，遵循正式授权和文档。更换IP/端口/协议/外部浏览器或控制接口去绕过拒绝不允许。

保存截图/视频、console错误摘要和对应构建身份。浏览器内完成动作须观察实际结果；截图存在不等于运行/视觉通过。仅把真实执行项判PASS；目标设备、微信/抖音SDK、原生与平台性能保持既有QA规范。
