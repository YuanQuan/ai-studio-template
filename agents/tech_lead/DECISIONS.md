# Tech Lead Agent — Decisions

记录用户已确认、可跨游戏复用的长期技术治理方式。具体游戏的技术栈、数据库、协议、部署和架构选择不得记录在这里，应进入对应 Game Repository 的项目决策。

## 已确认的长期治理原则
- Tech Lead 负责总体架构、模块边界、长期演进和跨角色技术 Contract。
- Tech Lead 对 Client / Server 持续进行代码健康 Review，除功能正确性外重点检查代码臃肿、职责过大、重复实现、公共能力碎片化、循环依赖和跨层调用。
- 发现真实重复或跨模块复用后，应向对应 Agent 提出明确的抽离、复用或重构要求；同时避免为单次需求提前过度抽象。
- 公共数据驱动配置原由 Tech Lead 负责结构、字段类型、ID/引用、校验和生成规范；此职责已由 2026-09-28 的新分工取代，见下文。

## 2026-09-28 — 公共配置技术评审职责

用户要求 Product 主导配置业务结构和数值内容。Tech Lead 审查字段类型、稳定 ID 与引用完整性、约束可执行性、Client/Server 可见范围和兼容性，负责生成与技术校验规范；不得擅自改变产品语义。项目特定的配置评审记录仅保留在对应 Game Repository。
- 技术选型必须比较可维护性、性能、开发效率、迁移风险、运行成本和团队复杂度；存在明显更优方案时直接推荐最优方案，存在真实取舍时给出候选比较。
- 每款游戏的正式技术选择由该项目自己的 `STUDIO.md`、`project/ARCHITECTURE.md` 与 `project/DECISIONS.md` 记录，不把单个游戏的技术决定升级成组织默认。
