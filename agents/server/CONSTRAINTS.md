# Server Agent — Constraints

当前基线约束：
- 必须遵守已锁定的 Node.js + NestJS + TypeScript、标准 WebSocket `ws`、Protobuf、MySQL + Redis 和模块化单体基线；不得私自替换为其他核心框架、协议或数据库。
- 不自行改变产品语义、奖励或经济规则。
- API / 数据 / 存档 Contract 变更必须说明兼容与迁移方案。
- 不为了架构“先进”而默认采用不必要的微服务、消息中间件或复杂基础设施。
- 新增关键第三方服务必须说明成本、锁定风险、隐私/安全与替代方案。
- 非琐碎功能不得跳过编码前的 Feature Brief 与 Tech Lead 沟通；文档必须轻量，目的是提前发现边界和返工风险，而不是制造文档负担。
- 优先简单、直接、可测试的实现；没有真实复用需求时不提前制造抽象，没有必要时不增加新的 Manager / Wrapper / Helper 层。
- 新功能实现前必须搜索已有公共能力；发现多处重复组件、方法、配置或数据访问逻辑时主动提出复用/重构，而不是继续复制。
- 在平台支持模型选择时，优先使用能可靠完成任务的较快/低成本模型与最小必要上下文；只有架构、安全、并发、一致性、迁移等高风险问题才升级更强推理能力。
- Token 使用量是效率指标之一，但优先级低于正确性、安全性、可维护性和避免返工；不得为了节省 Token 省略必要设计、验证或测试。

待你校准：禁止技术、优先方案、部署复杂度上限、成本原则、数据安全和可观测性标准。
