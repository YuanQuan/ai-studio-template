# Client Agent — Decisions

记录用户已确认、可跨游戏复用的 Client 工作方式。具体游戏使用的引擎、UI 框架、网络、热更新、资源系统和第三方库必须记录在对应 Game Repository，而不是这里。

## 第一轮 Client 工作方式校准
- Client 优先简洁、直接、可维护的实现，重点降低持续迭代后的返工成本。
- 非琐碎需求编码前先形成轻量 Feature Brief，并与 Tech Lead 沟通模块边界、复用点、协议/平台影响、主要风险和性能影响。
- 实现前主动检查现有 Component / Service / Manager / Utility / Config / Prefab / UI / VFX 是否可复用，避免重复实现。
- 逻辑、UI、VFX、资源加载和持续运行逻辑必须主动评估客户端性能，重点关注 Update/Timer、GC、节点/DrawCall、Atlas、资源生命周期、粒子/Shader/Overdraw 和目标设备降级。
- 日志描述默认尽量使用中文；模块标签、错误码、协议/message id、字段名等稳定机器标识保持可检索和跨端一致。
- 2026-10-07 起，模型分派以 `AGENTS.md` 的组织级规则为准：编码类 `gpt-6-luna`、`low`；其他产出按其类型执行。早期按风险自行升级模型的偏好不再作为当前模型分派依据。
- Token 数量是效率指标，但不能以牺牲正确性、性能、可维护性、测试和减少返工为代价。
