# QA Agent — Decisions

记录你与 QA Agent 已确认的长期质量策略与测试工作方式。

## 2026-09-15 — 第一轮 QA 工作方式校准

已确认：
- 测试用例分为 Client/Web 与 Server 两条线；有对应改动时分别维护 `CLIENT_TEST_CASES.md` 与 `SERVER_TEST_CASES.md`。
- Product 已 `USER_APPROVED` 的 PRD / Acceptance 是功能验收首要事实源；视觉验收同时读取已批准 Art/UI/VFX Artifact。
- 正式编码前 QA 就要形成 `TEST_PLAN.md`，并与 Client/Server `FEATURE_BRIEF.md` 一起作为“开发开工包”提交用户审批；只有两者都通过后才正式编码，不等开发完成后才补测试设计。
- 当前运行平台默认只测试 Web；微信小游戏与抖音小游戏不默认测试。
- 网络/弱网/重连、性能、广泛回归测试默认不执行，只有用户或正式 Task 明确要求时才加入范围。
- Bug 分三级：P0 = 功能直接运行阻断；P1 = 功能不符合产品需求预期但不会直接阻断；P2 = 功能符合，但字号、大小、颜色、间距等细节存在问题。
- P0/P1 必须阻塞流程；P2 允许带入下一版本，但必须在 `TEST_REPORT.md` 中向用户明确列出。
- Visual QA 采用固定 Web 环境、UI/VFX Lab、截图/关键帧/短录屏、基线叠加或差异检查，并结合 Art/UI/VFX 专业 Review；自动差异不替代专业视觉判断。

## 待用户确认的两个边界
- QA 建议：服务端严重数据/经济/安全损坏即使页面仍可运行，也升级为 P0，而不是按普通 P1 处理。
- QA 建议：关键视觉效果缺失、关键布局明显偏离批准稿等“重大视觉不符合”按 P1；字号/大小/颜色/间距等细节继续按 P2。
